# Scope and numerical certificate

This scratch implementation encloses the exact world-Z coordinates of a static
input mesh under its stored affine Matrix4. It also encloses the ordinary
binary64 evaluation of that same source-vertex transform. It does **not** certify
the coordinates generated by CSG, triangle classification, volume, or the later
consumer transformation of CSG output.

Files:

- `world-z-bounds.mjs`: `worldZBounds(geometry, matrixWorld)`,
  `worldZBoundsFromBox(box, matrixWorld)` and `intervalOverlapHeightMm(a, b)`.
- `test-world-z-bounds.mjs`: independent exact BigInt dyadic oracle.
- `test-world-z-bounds.json`: recorded check results.

## Arithmetic argument

For finite binary64 operands, the correctly rounded result of a multiplication
or addition is either the exact real result or a nearest representable value.
Moving the rounded result one representable value down and up therefore encloses
the exact real result. This remains true at zero and in the subnormal range:
`nextDown(0) = -Number.MIN_VALUE` and `nextUp(0) = Number.MIN_VALUE`.
An enclosure that reaches infinity is rejected, rather than assumed usable.
Multiplication by exact zero has the exact enclosure `[0, 0]`.

For intervals `[a,b]` and `[c,d]`, addition is monotone, so outward rounding of
`a+c` and `b+d` encloses every sum. Repeated application encloses

`e[2]*x + e[6]*y + e[10]*z + e[14]`.

The same monotonicity also encloses evaluation with rounded intermediate
products and sums. The implementation does not depend on an epsilon, magnitude
threshold, model identity, orientation, triangle count, or units heuristic.
Negative coefficients naturally include reflections; the other two coefficients
include arbitrary shear and rotation.

The matrix must have finite entries and the exact bottom row `[0,0,0,1]`.
Projective transforms are rejected. A non-finite position, empty/unsupported
position attribute, or non-finite arithmetic enclosure returns
`certified: false`. This includes cancellation cases where the exact final dot
product is finite but an intermediate floating-point product overflows.

## From vertices to solid height

An affine coordinate on a triangle is a convex combination of that coordinate
at its vertices. Minima and maxima over its exact geometry therefore lie inside
the extrema of all transformed input vertices. Reading unused/index-excluded
positions can widen the bound but cannot invalidate it. Skinning and morphing
must already be materialized in the supplied static position data. The bound is
relative to the stored matrix and returned position values, not an earlier
unrounded source representation.

Given certified bounds `[a.min,a.max]` and `[b.min,b.max]`, the actual geometric
intersection is contained in

`[max(a.min,b.min), min(a.max,b.max)]`.

If the upper endpoint is no larger than the lower endpoint, its possible height
is zero. Otherwise, rounding their difference upward and then multiplying by
1000 with upward rounding provides a conservative height in millimetres, for
metre-based input coordinates. Non-finite results return `null`.

This height also bounds ordinary rounded `(zMax-zMin)*1000` for any output whose
vertices have independently been proven to lie in that interval. That final
condition is not established for existing CSG output by this helper.

For multiple brush pairs, the entire object's intersection can contain pieces at
different elevations. The relevant height is that of the union's enclosing Z
interval. Small height for each individual pair does not imply small aggregate
height. The caller must union the nonempty pair-overlap intervals before applying
the final height test, and retain the consumer's Duplicate exception.

## Bounding-box corners versus vertex scans

Corners suffice if the local box is first proven to contain all local input
vertices. The transformed exact mesh is contained in the transformed box, and an
affine world-Z function reaches its box extrema at corners. Each corner still
needs the directed-rounding calculation; an ordinary `Box3.applyMatrix4` does
not provide that arithmetic certificate.

A stale or unverified cached `geometry.boundingBox` is not such a certificate.
Computing local coordinate extrema by scanning every finite position uses exact
comparisons and establishes a valid local box. It may then be cached against
the actual immutable geometry identity/version. That can save repeated scans
across placements, but it is less tight than transforming the mesh vertices:
rotation/shear may choose box corners absent from the actual mesh. The scan API
establishes the mesh bound without a cache-ownership assumption. The box API
evaluates all eight corners and requires the caller to establish local box
containment and immutability. It does not accept a cached box as proof merely
because the object has a `boundingBox` field.

Ordinary rounded evaluation of the affine Z dot product is also monotone in each
coordinate, with direction set by that coordinate's coefficient, as long as
intermediate arithmetic is finite. Thus the outward corner intervals also
enclose rounded source-vertex transforms for all vertices contained in the box.

## Recorded independent validation

The deterministic oracle decodes binary64 values into signed BigInt significands
and powers of two. It performs exact products, sums, comparisons and convex
combinations without using the interval algorithm or floating-point tolerance.

- 40,010 affine point cases: 27,243 certified, 12,767 explicitly uncertified;
  no incorrect enclosure. Certified cases also enclose the rounded transform.
- 3,000 meshes: 2,968 certified; all vertices and 2,968 independently formed
  exact triangle-interior convex combinations lie inside the returned bounds.
- The eight-corner box API certifies 2,968 of the same meshes and encloses all
  20,842 exact transformed source vertices and their ordinarily rounded Z values.
- 30,000 interval-height cases: 29,997 certified, 3 overflow cases rejected;
  no underestimated exact or ordinarily rounded height.
- Explicit checks cover positive/negative zero, subnormal products, underflow,
  cancellation, huge finite values, overflowing intermediates, reflections,
  shear, non-affine matrices, invalid positions and 10.1 mm threshold neighbors.

These property tests support the arithmetic argument; they do not convert an
input certificate into a proof about the current CSG implementation's output.

## Concrete output counterexample

`reproduce-output-overrun.mjs` reproduces a decision difference against the
`vertical-control` scratch variant, which disables the singleton shortcut,
controls mirrored coplanar orientation, and preserves the exact affine result
matrix. It calls the actual consumer classification, oriented-size and tolerance
functions; it does not modify their policy.

- A: closed box 4 x 4 x 1.8 metres, world transform `z += 0.2*x`.
- B: closed box 1 x 1 x 0.01009999999999999 metres, translated by 0.3 metres in X.
- Certified input-overlap height: **10.099999999999998 mm**, below 10.1 mm.
- Actual output height: **10.100000000000026 mm**, above 10.1 mm.
- Output volume: **10,099,999.999999998 mm3**, classified `Overlapping`.
- Input volume difference ratio: **0.9996493055555555**, so the 0.1 Duplicate
  necessary condition fails by a wide margin. Neither tolerance nor fill-ratio
  filtering removes the output under the current consumer implementation.

B is strictly contained in A. In A's local frame, B's X lies in [-0.2,0.8], Y in
[-0.5,0.5], and Z in approximately [-0.16505,0.04505], all strictly inside A.
Thus the exact intersection is B and its correct mathematical height is below
the threshold. The emitted output repeats B after converting it into A's frame
and back; that floating-point round trip produces exactly the same excessive
height even without CSG clipping. Float64 attributes and preservation of A's
full affine matrix do not eliminate this effect.

The difference is tiny, but the consumer compares a strict numeric boundary, so
this is a real decision mismatch. The input certificate itself remains correct.
Using it as an early exit would remove an existing numerical false positive;
it cannot be described as preserving every current output. Adding an arbitrary
margin would not prove safety for all scales or transformations.

The bounded search also found larger overruns with severely conditioned finite
shear matrices. Those are recorded separately in `output-overrun-search.json`;
the ordinary 0.2-shear case is the primary reproduction and does not rely on
extreme coordinate magnitudes.
